它解决什么

四件事，都是国内环境下真会遇到的那四件。

mirror default · cn · tuna aliyun · ustc probe 500ms → 缓存 6h

国内网络

  • 内置 default / cn / tuna / aliyun / ustc 五档
  • 装第一个工具时做真实探测（500ms HEAD，结果缓存 6h）：官方源通就直连，不通自动落国内档
  • 也可以手动 pk mirror use cn 锁死某一档
pair node@22.23.4 → npm@12.2.2 replaced 10.9.9

npm 配对

  • npm 不是独立工具，是 node 的伴生包，不单独暴露一个版本
  • 按 node 的精确版本反查「最新兼容的 npm」，替换掉发行版自带的旧版
  • 按补丁号判分界（22.22.2 → npm 12.x、24.15.0 → 12.x），排除预发布
verify sha256 × 2 源 TOFU 表 之后完全离线可验

校验

  • 首次安装要求至少两个源给出相同摘要，并写进 TOFU 表
  • 之后同一版本完全离线可验证
  • 源之间矛盾时硬失败，并告诉你产物与哪个源一致
uninstall pk uninstall --all --self 残留 0

卸载

  • 台账是唯一事实源：只删自己记录过的目录，1.9.2 起还会核一次「这条 path 真的在 ~/.packnest/tools 下」，坏记录不会删到别处
  • 切版本靠 shim 原子重指，卸载回到零残留
  • pk uninstall --all --self 连 pk 自己一起清（Windows 上延时删除）
长尾工具
内嵌 6 个 provider，其余靠 自写 TOML 清单（~/.packnest/providers/<id>.toml）：索引、产物、校验、布局、伴生包全在清单里声明，纯数据不执行代码；字段见 docs/providers.md。
下载
Range 续传 + 默认多连接（≥8MB、冷启动、源支持 Range 时按大小自适应 2~8 段，异常自动退回单流；--jobs 1 可强制单流）。实测 48MB 的 node 包：单流 1.46s → 8 段 0.84s。索引走 gzip 传输，go 的索引 2.28MB → 557KB。
缓存
产物与索引缓存默认在 ~/.packnest/cache；CI 或多机预热可以用 PK_CACHE=<目录> 把它搬到别处（台账、shim、锁不动），--purge 也不会动那个目录。 热缓存对全新机器同样有效：缓存里记着「上游公布的摘要 → 归档」的别名，新 runner 只发一次几 KB 的校验和请求就能命中 50 MB 的归档，不必先下再算摘要（1.8 起）。
体积
单个 Go 二进制，CGO_ENABLED=0，六平台构建，只依赖两个第三方库（semver、toml）。

命令

10 个，命令面固定。全局开关 --json 是 GUI 与脚本的唯一契约。

命令做什么
install装工具（多个工具跨工具并行：下载、校验、解压同时跑，落盘与台账仍单线程）；无参数时按当前目录的 pk.toml 全装并刷新 pk.lock；只有 package.json 时读它的 engines.node
uninstall工具@版本 删一个；工具 删该工具全部版本（先列版本再确认）；--all 清掉一切（--purge 连根删、--self 连自己）
use切换全局默认版本；--project 固定到当前项目
list已装工具与占用空间，版本落后时提示可升级（只读索引缓存、不联网）；pk list node 看单个工具的全部可装版本（--major 22 / --all）
which把 shim 解析回真实二进制路径
mirrorlist / probe / use / write 四个子命令管理镜像档
doctor体检 PATH、台账、镜像、全局包、其他版本管理器；--fix 自动修 PATH 托管块与 pk/packnest 入口
env输出 shell 片段；--write 写进托管块（Windows 走注册表用户 Path，不受执行策略限制）
gc回收零引用版本与超限缓存；--keep 2 每个工具保留最新 2 个
upgrade把已装工具一次升到索引最新（旧版本保留、全局默认跟着切、npm 随 node）；--dry-run 先看要升什么。
升级 pk 自己：pk upgrade --self（地址按网络自动选 gitee/GitHub，验签后原子替换；brew/scoop 装的只提示渠道命令）

失败时 --json 额外输出一条 {"schema":1,"error":{"code","args","msg","exit"}}（1.8 起，只增不改；人读的 stderr 与退出码不变）

全局开关 --json（GUI 与脚本的唯一契约）· --offline · --yes · --root · --lang en（英文输出，也可 PK_LANG=en）；退出码固定 0 成功 / 1 通用 / 2 用法 / 3 网络 / 4 校验 / 5 锁被占用。

--dry-run 是只读预览：不下载、不解压、不写 pk.lock、不清残留、不改 config.toml（1.5.1 起）。

发布链可验签：checksums.txt 带 sshsig 签名（checksums.txt.sig），安装脚本在比对 sha256 之前先验签——镜像站与自托管源改不了清单（brew/scoop 只认 sha256，这是渠道边界）。

长尾工具不用等发版：把 ~/.packnest/providers/<id>.toml 放进去即可（纯数据、不执行代码；校验和、镜像回退、伴生包都在清单里声明，pk doctor 会指出清单哪一行不对）。

桌面端

可选 · 独立产物 · 必须先装 CLI。

GUI（pk-desktop，原生界面：纯 Go、无 webview）只是 CLI 的可视化补充： 不 import 任何内部包，每个操作都是子进程调 pk <命令> --json， 业务真相始终在 CLI 和 ~/.packnest 里。所以它永远比 CLI 晚半步，也不会替你下载第二份运行时。

  • 已装工具表：可升级提示（点一下就 pk install <工具>@latest）、weak / 未校验 / npm 徽标、复制安装路径
  • 安装队列：多条 spec 依次装，每行独立进度（NDJSON 的 progress 事件）
  • 镜像档切换 + 各源延迟探测，写 ~/.npmrc 前自动备份
  • 体检页：全局包表格化、--probe 用 node 实测原生模块、一键修复（pk doctor --fix）
  • 回收页：预演 / 真删、--keep N 每个工具保留最近 N 个版本
  • 只读查看 which（命令 → 真实路径）与 env（PATH / 变量）
  • 深浅色切换、中英双语（顶栏切换，默认跟系统语言）
  • 检查更新：同时看桌面端与 CLI 的版本，下载地址按当前网络自动挑（gitee / GitHub），一键升级并提示重启
  • 开机自启（默认关，只写用户级条目：LaunchAgent / HKCU Run / XDG autostart）

前置条件
先装 CLI（pk）—— 没装时界面顶部会直接给出当前平台的安装命令（Windows 走 PowerShell，其余走 sh）并带复制按钮。 macOS 是 ad-hoc 签名，首次打开要在「系统设置 → 隐私与安全性」放行一次；Windows/Linux 不需要任何 webview 运行时（Linux 托盘另需 libayatana-appindicator3）。 浏览器形态 pk-desktop --serve → http://127.0.0.1:7799/ 保留为兜底页（0.12 起冻结，排版与功能以原生界面为准）。
不是什么
不是第二个安装器：没有自己的台账，也不想再实现一遍升级逻辑 —— 升级 CLI 交给 pk upgrade --self， 升级桌面端由 GUI 自己换产物（下载 → 验签 → 比 sha256 → 替换，提示重启）；scoop 装的只提示 scoop update packnest-desktop。卸载仍指回 CLI（pk uninstall --all --self）。

常见问题

四条被问得最多的。

它和 nvm / proto 有什么区别？

nvm 只做 node，proto 是通用版本管理器但不带国内镜像探测。packnest 的重点是「国内网络下装得下来 + 装完能干净卸掉」，六平台单二进制，不依赖 nvm 的 shell 函数注入。

国内镜像失效了怎么办？

探测是每次冷启动做的，缓存 6 小时。任一档失效会落到下一档；全都不通时用 --offline 走本地缓存，或 pk mirror write 自己写一档。

为什么 npm 不能单独装？

因为 npm 是 node 的伴生包：脱离某个 node 版本谈 npm 版本没有意义。装 node 时按精确版本反查最新兼容的 npm 一起装，避免出现 node 22 配着 node 18 时代 npm 的情况。

装了桌面端还要装 CLI 吗？

要。桌面端每个操作都是子进程调 pk --json，业务真相在 CLI 和 ~/.packnest 里。没装 CLI 时界面顶部会直接给出当前平台的安装命令。

In English

packnest (command pk) installs Node/npm/pnpm/bun/Go/Python as a single zero-CGO Go binary for six platforms, with only two third-party dependencies. It ships China mirror presets plus real reachability probing, pairs the newest npm compatible with the exact Node version being installed, verifies artifacts against multiple checksum sources (TOFU, offline-verifiable afterwards), and uninstalls back to zero residue — pk uninstall --all --self even removes pk itself.
