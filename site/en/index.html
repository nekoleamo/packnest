What it solves

China network
Five built-in profiles: default / cn / tuna / aliyun / ustc. The first install probes for real (500ms HEAD, cached for 6h): reachable upstream means direct, otherwise it falls back to a domestic mirror automatically.
npm pairing
npm is not a standalone tool but a companion of Node: the newest npm compatible with the exact Node version is looked up and replaces the older one shipped in the tarball (boundaries are patch-level, pre-releases excluded).
Checksums
The first install requires at least two sources to agree on the digest and records it in a TOFU table; every later install of that version verifies fully offline. If sources disagree it fails hard and tells you which source the artifact actually matches.
Uninstall
The ledger is the only source of truth: only directories it recorded are removed, version switches are atomic shim re-points, and uninstalls leave zero residue. pk uninstall --all --self removes pk itself too (delayed delete on Windows).
Long tail
Six providers are embedded; everything else comes from your own TOML manifest (~/.packnest/providers/<id>.toml) — index, artifact, checksums, layout and companion packages are declarative data, no code executed. Field reference: docs/providers.md.
Downloads
Range resume plus parallel sharding by default (≥8MB, cold start, Range-capable source; 2–8 shards picked by size, any trouble falls back to one stream; --jobs 1 forces a single stream). Measured on a 48MB node tarball: 1.46s → 0.84s with 8 shards. Indexes travel gzipped: the Go index drops from 2.28MB to 557KB.
Cache
Artifact and index caches live in ~/.packnest/cache by default; PK_CACHE=<dir> moves them elsewhere for CI or multi-machine warmup (ledger, shims and locks stay put), and --purge never deletes that directory.
Footprint
One Go binary with CGO_ENABLED=0, built for six targets, depending on exactly two third-party libraries (semver, toml).

Desktop app optional · separate artifact · requires the CLI

The GUI (pk-desktop, Wails + Vue3) is a visual supplement to the CLI, not a second installer: it imports no internal packages and every action is a subprocess call to pk <command> --json, so the truth always stays in the CLI and in ~/.packnest.

What it does
  • Installed-tools table with an upgrade hint (one click = pk install <tool>@latest), weak / unverified / npm badges, copy install path
  • Install queue: multiple specs run one after another, per-row progress (the NDJSON progress event)
  • Mirror profile switching with latency probing; writing ~/.npmrc backs it up first
  • Doctor page: global packages in a table, --probe to really load native modules with node, Fix now (pk doctor --fix)
  • Reclaim page: preview or delete, --keep N keeps the newest N versions per tool
  • Read-only which (command → real path) and env (PATH / variables) views
  • Light/dark toggle and a Chinese/English UI (header switch, follows the system language)
  • Launch at login (off by default; user-level entry only: LaunchAgent / HKCU Run / XDG autostart)

Requirements
The CLI must be installed first — if it is missing, the header shows the install command for your platform (PowerShell on Windows, sh elsewhere) with a copy button. macOS builds are ad-hoc signed: allow the app once under System Settings → Privacy & Security. Linux needs GTK4 + WebKitGTK 6.0 (libgtk-4-dev libwebkitgtk-6.0-dev). No desktop runtime? Use the browser form: pk-desktop --serve → http://127.0.0.1:7799/, same features.
What it is not
Not a second package manager: no downloader of its own, no separate ledger, no self-updater. Uninstall and upgrade still go through the CLI (brew upgrade packnest, pk uninstall --all --self).
