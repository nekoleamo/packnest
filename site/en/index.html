What it solves

China network
Five built-in profiles: default / cn / tuna / aliyun / ustc. The first install probes for real (500ms HEAD, cached for 6h): reachable upstream means direct, otherwise it falls back to a domestic mirror automatically.
npm pairing
npm is not a standalone tool but a companion of Node: the newest npm compatible with the exact Node version is looked up and replaces the older one shipped in the tarball (boundaries are patch-level, pre-releases excluded).
Checksums
The first install requires at least two sources to agree on the digest and records it in a TOFU table; every later install of that version verifies fully offline. If sources disagree it fails hard and tells you which source the artifact actually matches.
Uninstall
The ledger is the only source of truth: only directories it recorded are removed (since 1.9.2 it double-checks that the recorded path really lives under ~/.packnest/tools, so a corrupt record can never delete something else), version switches are atomic shim re-points, and uninstalls leave zero residue. pk uninstall --all --self removes pk itself too (delayed delete on Windows).
Long tail
Six providers are embedded; everything else comes from your own TOML manifest (~/.packnest/providers/<id>.toml) — index, artifact, checksums, layout and companion packages are declarative data, no code executed. Field reference: docs/providers.md.
Downloads
Range resume plus parallel sharding by default (≥8MB, cold start, Range-capable source; 2–8 shards picked by size, any trouble falls back to one stream; --jobs 1 forces a single stream). Measured on a 48MB node tarball: 1.46s → 0.84s with 8 shards. Indexes travel gzipped: the Go index drops from 2.28MB to 557KB.
Cache
Artifact and index caches live in ~/.packnest/cache by default; PK_CACHE=<dir> moves them elsewhere for CI or multi-machine warmup (ledger, shims and locks stay put), and --purge never deletes that directory. A warm cache also works on a brand-new machine: the cache records "published digest → archive" aliases, so a fresh CI runner fetches a few KB of checksums and hits the 50 MB archive instead of downloading it (since 1.8).
Footprint
One Go binary with CGO_ENABLED=0, built for six targets, depending on exactly two third-party libraries (semver, toml).

Upgrade pk itself: pk upgrade --self (source auto-picked by network: gitee/GitHub; signature checked, replaced atomically; brew/scoop installs only get the command)

On failure --json also emits {"schema":1,"error":{"code","args","msg","exit"}} (since 1.8, additive only; the human stderr line and exit code are unchanged)

Global flags: --json (the only contract for GUIs and scripts) · --offline · --yes · --root · --lang en (English output; PK_LANG=en also works). Fixed exit codes: 0 ok / 1 generic / 2 usage / 3 network / 4 checksum / 5 locked.

--dry-run is a read-only preview: no download, no extraction, no pk.lock, no stale sweep, no config.toml change (since 1.5.1).

Releases are signed: checksums.txt ships with an sshsig signature (checksums.txt.sig) and the install script verifies it before comparing sha256 — mirrors and self-hosted sources cannot rewrite the manifest (brew/scoop only check sha256; that is their limit).

Long-tail tools need no release: drop ~/.packnest/providers/<id>.toml in (pure data, no code executed; checksums, mirror fallback and companion packages are declared in the manifest, and pk doctor points at the offending line).

Desktop app optional · separate artifact · requires the CLI

The GUI (pk-desktop, native UI — pure Go, no webview) is a visual supplement to the CLI, not a second installer: it imports no internal packages and every action is a subprocess call to pk <command> --json, so the truth always stays in the CLI and in ~/.packnest.

What it does
  • Installed-tools table with an upgrade hint (one click = pk install <tool>@latest), weak / unverified / npm badges, copy install path
  • Install queue: multiple specs run one after another, per-row progress (the NDJSON progress event)
  • Mirror profile switching with latency probing; writing ~/.npmrc backs it up first
  • Doctor page: global packages in a table, --probe to really load native modules with node, Fix now (pk doctor --fix)
  • Reclaim page: preview or delete, --keep N keeps the newest N versions per tool
  • Read-only which (command → real path) and env (PATH / variables) views
  • Light/dark toggle and a Chinese/English UI (header switch, follows the system language)
  • Check for updates: sees both desktop and CLI versions, picks the download source from current network conditions (gitee / GitHub), upgrades in place and asks for a restart
  • Launch at login (off by default; user-level entry only: LaunchAgent / HKCU Run / XDG autostart)

Requirements
The CLI must be installed first — if it is missing, the header shows the install command for your platform (PowerShell on Windows, sh elsewhere) with a copy button. macOS builds are ad-hoc signed: allow the app once under System Settings → Privacy & Security. Windows and Linux need no webview runtime (the Linux tray icon wants libayatana-appindicator3). The browser form (pk-desktop --serve → http://127.0.0.1:7799/) is kept as a frozen fallback page — layout and features follow the native app.
What it is not
Not a second package manager: no separate ledger, and no second implementation of upgrading — the CLI upgrades itself via pk upgrade --self, while the desktop app swaps its own artifacts (download → verify signature → sha256 → replace → ask to restart); scoop installs only get scoop update packnest-desktop. Uninstall still goes through the CLI (pk uninstall --all --self).
